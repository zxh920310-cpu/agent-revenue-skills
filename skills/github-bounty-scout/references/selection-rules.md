# Bounty Selection Rules

## Recommended

- Explicit USD amount, ideally $20-$50.
- Clear acceptance criteria.
- Small implementation surface:
  - docs
  - tests
  - examples
  - install/setup
  - typo/copy
  - small bug fix
  - label or alias change
- Low competition:
  - zero to two comments;
  - no matching open PR;
  - no obvious "claimed" comment.
- Active maintainers:
  - issue or repo updated recently;
  - similar PRs reviewed or merged recently.

## Watchlist

- No amount but strong open-source portfolio value.
- Non-USD payout with clear scope.
- Good C-strategy contribution but not directly payable.
- Slightly larger task that still looks under two hours.

## Reject

- Missing reward amount when the user needs bounty income.
- Task requires external signup or a bounty platform claim.
- Task requires payment, wallet, bank, PayPal, Venmo, Stripe, tax, identity, KYC, or email verification.
- Task requires API keys, OAuth, customer data, company files, CRM/ERP/Excel business data, or private repository data.
- Security challenge, pentest, CVE, exploit, smart-contract challenge, or unclear crypto/payment flow.
- Existing matching PR.
- Creator-only or assigned-only issue.
- Broad PRD, full feature build, redesign, architecture rewrite, long-term maintenance, or estimated over six hours.

## Manual Verification

Before executing, inspect:

1. Issue body.
2. Latest comments.
3. Open PRs mentioning the issue number or title.
4. Contribution rules.
5. Test/build instructions.
6. Recent maintainer activity.

If any of these checks are unclear, do not start coding.
